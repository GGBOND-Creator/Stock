# A 股资金控制与运动概率模型

更新时间：2026-08-17（Asia/Shanghai）

## 1. 目标

本模型回答两个彼此关联但不能混同的问题：

1. 某段时间发生了什么资金或持仓运动？
2. 在当时可获得的证据条件下，谁对这部分资金拥有哪一种控制权？

最终输出是条件概率，而不是身份断言：

```text
P(控制主体=c，控制角色=r | 截至决策时点可用的证据 E)
```

同一个资金运动事件的所有候选主体概率必须合计为 1；不能识别的概率质量必须保留在 `CONTROLLER_UNKNOWN`。

## 2. 为什么不能直接从成交额推断“谁在买”

二级市场每一笔成交同时有买方和卖方。成交额表示交换规模，不表示有同等金额的资金凭空流入市场。只有先划定参与者群体，才能定义净买入：

```text
某主体组净买入 = 该组买入金额 - 该组卖出金额
```

在相同市场边界和时间区间内，各主体组净买入之和理论上接近 0；差异主要来自统计范围、费用、一级发行、申赎和数据缺失。因此，“某股票主力净流入”若没有订单身份、席位归属或持仓变化等独立证据，只能记录为代理量，不能作为控制主体事实。

## 3. 控制不是单一关系

同一笔资金可能同时涉及不同主体：

| 控制角色 | 含义 | 例子 | 不能自动推出的结论 |
| --- | --- | --- | --- |
| `beneficial_owner` | 最终承担收益与损失 | 基金份额持有人、保险保单资金受益集合 | 不一定直接决定买卖 |
| `mandate_decision_maker` | 按授权决定资产配置 | 基金管理人、保险资管、企业投资委员会 | 不等于资金最终所有人 |
| `trader_executor` | 执行具体订单 | 交易员、算法执行系统、经纪通道 | 不等于拥有投资决策权 |
| `custodian_nominee` | 托管、登记或名义持有 | 托管银行、中央结算、互联互通名义持有人 | 不等于受益所有人或决策人 |
| `inferred_group` | 只能识别到统计群体 | 个人投资者、公募基金、境外投资者 | 不能冒充具体自然人或法人 |

例如，某公募基金的受益所有人是基金份额持有人集合，投资决策通常由基金管理人按基金合同执行，托管银行负责资产托管。把托管银行写成“资金控制人”会造成严重身份错误。

## 4. 数据表

机器可读主契约：`data/contracts/capital_control_distribution_v1.schema.json`。

首个注册表目录：`data/capital_control/a_share/`。

### `flow_events.csv`

保存独立观察到的资金或持仓运动，不包含控制人猜测。主要字段：

- `event_time`：运动发生时间；
- `available_time`：证据最早可用于模型的时间；
- `flow_measure`：成交额、买单额、卖单额、持仓变化、申赎等；
- `side`：`buy`、`sell`、`net_buy`、`net_sell` 或 `unknown`；
- `observed_amount` / `amount_unit`：来源原始金额及单位；
- `evidence_kind`：观察、派生或代理。

### `controllers.csv`

登记自然人、法人或聚合主体类别，并保存身份依据。没有法律实体标识或官方披露时，不建立具体人物节点。

### `capital_pools.csv`

登记被控制的资金池，例如公募产品、保险账户、企业自有资金、资管计划或只能聚合识别的个人账户集合。

### `control_relations.csv`

将资金池连接到主体，并明确控制角色、有效期、可得时间、控制比例和证据来源。关系随时间变化，不能用今天的基金经理回填过去。

### `capital_positions.csv`

保存资金池在报告期末公开披露的持仓观察，例如公募基金季报中的股票、持仓数量、持仓市值和占净值比例。持仓快照说明“资金池当时持有什么”，不说明期间哪一笔买单由谁下达，也不自动生成资金运动概率。

### `controller_probability_distribution.csv`

这是用户所说的“资金运动分布概率表”。一行代表一个运动事件分配给一个候选主体和控制角色的条件概率。关键约束：

- 同一 `flow_event_id` 的 `probability` 合计为 1；
- 未解释部分进入 `CONTROLLER_UNKNOWN`；
- `estimated_signed_amount` 是概率乘以事件金额后的期望值，不是直接观察；
- `probability_status` 区分已观察身份、有证据估计、仅先验和未解决；
- 每次估计必须记录 `probability_method` 与 `evidence_ids`。

## 5. 概率如何形成

首版采用可解释的贝叶斯分解：

```text
后验概率 ∝ 似然 × 先验

P(c,r | E,t) ∝ P(E | c,r,t) × P(c,r | t以前的持仓与资金规模)
```

先验只能使用决策时点之前已公布的持仓、基金规模、股东结构和账户统计。似然来自本次事件的独立证据，例如明确披露的增减持、可核验的大宗交易双方、基金后续持仓变化或带身份的订单数据。报告期末持仓在公告日之前不可用。

第一阶段不训练复杂模型。先用规则生成可审计概率，并保留大比例 `unknown`；积累足够带标签事件后，再做时间顺序校准，检查 Brier score、log loss 和概率分箱可靠性。

## 6. 证据等级

| 等级 | 可免费或低成本获得的例子 | 可支持的结论 |
| --- | --- | --- |
| A 直接身份证据 | 官方增减持公告、回购公告、基金定期报告中的产品持仓、可核验大宗交易披露 | 特定主体或资金池在特定报告口径下的行为/持仓 |
| B 聚合持仓证据 | 公募季度持仓、前十大股东、融资融券余额、互联互通汇总 | 主体类别或资金池的区间变化，通常不能定位单笔交易 |
| C 交易通道证据 | 龙虎榜营业部、券商席位、托管或名义持有人 | 交易或登记通道；除非有独立证据，不能当作受益所有人 |
| D 行情代理 | 成交额、大单分类、价格方向、换手率 | 活跃度与方向代理，不能识别控制主体 |

公开数据通常只能把概率从“完全未知”推进到主体类别或资金池，很少能识别具体自然人。具体个人身份必须来自合法公开披露，不能通过去匿名化猜测生成。

## 7. 推荐的免费数据接入顺序

1. 巨潮资讯：股东增减持、回购、基金/机构持股、前十大股东及公告时间。
2. 中国证监会基金信息披露与基金公司定期报告：产品、管理人、基金经理、持仓和报告可得时间。
3. 交易所公开数据：融资融券、互联互通、大宗交易、龙虎榜；只使用其实际披露身份层级。
4. 上市公司财报：货币资金、交易性金融资产、回购与股权投资；这是公司控制的资产，不等于二级市场当天订单。
5. 行情数据：只作为运动规模、价格反应和代理特征，不直接生成主体身份。

## 8. 时间与验证规则

- 所有记录都保留 `event_time` 和 `available_time`；训练时只读取当时已经可得的证据。
- 基金季报、股东名册和财报是离散快照；两个报告期之间的交易路径通常不可识别。
- 概率模型必须与“全部未知”和“按历史资金规模比例分配”两个朴素基线比较。
- 每个时间窗口分别报告覆盖率、`unknown` 概率质量、校准误差和可识别主体数量。
- 若概率不能用后来公开的持仓或身份事件校准，就只能称为研究评分，不能称为真实概率。
