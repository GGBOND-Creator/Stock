# 自然环境模型

更新时间：2026-08-17

## 定义

自然环境模型现在是 [人的需求—资源—生产网络](HUMAN_NEED_RESOURCE_NETWORK.md) 的物质约束层。建设顺序从人的需求出发，经满足功能和转化过程，再记录其依赖的能源、矿产、土地、水、气候、生物条件和物流地理条件。

现实中的资源与环境约束先于并限制产业生产；“下位”只表示数据契约中的连接层，不表示自然环境从属于企业。A 股企业和股票不再是自然模型的起点，而是未来过程承载者映射的一种下游对象。

它不试图一次性还原完整地球系统。第一版只为已经审核的产业活动建立低成本、低算力、可手工维护的自然依赖记录；没有明确产业用途的全球种子行暂不扩展，也不进入股票运动模型。

## 当前建设顺序

```text
人的需求
  → 满足功能
  → 生产/转化过程
  → 资源与环境依赖候选
  → 具体地理单元及带时间戳的自然观察
  → 产业承载者暴露与约束状态
  → 企业/股票运动模型中的可审计通道
```

只有前一层对象有稳定标识和证据，才建立下一层关系。行业分类只能用来发现候选依赖，不能单独证明某家公司实际使用某种资源。

## 性质

| 性质 | 说明 |
| --- | --- |
| 低维 | 初始只使用少量字段，避免在数据不足时制造虚假的精确性 |
| 可迭代 | 每条记录都保留 `source_status` 和 `confidence`，后续可替换为正式数据 |
| 可映射 | 每个单元保留 `lat`、`lon`、`iso3` 和 `region`，便于可视化 |
| 可连接 | 字段应能连接到社会模型、行业、公司和市场价格 |
| 可复盘 | 记录更新频率和约束等级，用于观察变化而不是只保存静态事实 |
| 需求锚定 | 每条正式自然依赖都应连接到需求满足功能和已定义的转化过程；企业连接是可选的下游映射 |
| 时间安全 | 关系和观察都保留事件时间与可得时间，未来资料不能提前进入历史状态 |

## 与需求—资源网络及 A 股分支的接口

第一版优先建立四类对象或关系：

| 层级 | 回答的问题 | 例子 | 证据要求 |
| --- | --- | --- | --- |
| 需求/过程锚点 | 哪个需求满足过程需要自然条件 | 生猪及猪肉供给过程 | 需求—功能—过程结构 + 依赖证据 |
| 自然依赖 | 需要什么物质或环境条件 | 饲料粮、水、适宜温度 | 行业资料或独立来源；公司特定关系需更强证据 |
| 地理供给单元 | 依赖从哪里获得或在哪里发生 | 玉米产区、养殖基地所在流域 | 可核验地点与来源 |
| 状态观察 | 某时点供应或约束怎样变化 | 产量、价格、降水、水压力、运输中断 | 保留单位、频率、事件时间、可得时间和来源 |

正式关系不得仅凭常识自动生成。常识可以形成 `candidate`，经过来源核验后才能升级为 `imported` 或 `verified`。

## 初始数据库

| 文件 | 作用 |
| --- | --- |
| `data/natural_environment/global_environment_units.csv` | 全球自然环境单元种子表 |
| `data/natural_environment/natural_environment_dimensions.csv` | 自然环境模型维度定义 |

当前 12 条全球种子数据使用 `seed_unverified` 状态，只作为旧结构样例，不作为正式研究事实，也尚未与 A 股产业节点建立连接。它们暂时保留，但停止横向扩展。后续应从一个已审核产品开始，另行设计产业锚定的自然依赖契约，并用正式公开数据生成 `imported` 或 `verified` 记录。

## 核心字段

| 字段 | 定义 |
| --- | --- |
| `unit_id` | 自然环境单元唯一编号 |
| `unit_name` | 自然环境单元名称 |
| `unit_type` | 单元类型，例如国家资源、区域资源、产业产能 |
| `iso3` | 国家或地区 ISO3 代码 |
| `region` | 所属大区 |
| `lat` / `lon` | 可视化中心点 |
| `natural_dimension` | 所属自然环境维度 |
| `primary_resource` | 主要资源或约束对象 |
| `resource_role` | 该资源在世界模型中的作用 |
| `production_proxy` | 生产或供给能力的低维代理值 |
| `reserve_proxy` | 储量或长期禀赋的低维代理值 |
| `constraint_level` | 综合约束等级 |
| `climate_zone` | 粗略气候区 |
| `water_stress` | 水资源压力代理值 |
| `logistics_access` | 物流可达性代理值 |
| `update_frequency` | 建议更新频率 |
| `source_status` | 数据状态，例如 `seed_unverified`、`imported`、`verified` |
| `confidence` | 当前可信度 |
| `notes` | 备注 |

## 可视化

第一版可视化输出：

```text
reports/natural_environment_map.html
```

生成命令：

```powershell
.\.venv\Scripts\python.exe scripts\build_natural_environment_visualization.py
```

可视化暂时使用经纬度点位和表格联动，重点观察全球自然环境单元的分布、维度、约束等级和数据状态。后续如需更精确的地图边界，可再接入正式 GeoJSON 或 TopoJSON 底图。

## 与产业网和社会模型的关系

需求—资源网络先回答“人要满足什么、需要哪些转化过程和物质条件”；A 股分支再回答“哪些企业承载了这些过程，以及它们怎样连接到证券”；社会模型回答“主体如何组织和分配这些物质”。三者连接后，才能提出有关成本、产量、利润、政策、资本流动和市场预期的可检验假设。

例如，对“生猪及猪肉供给过程”，可以先把饲料粮、水、土地、能源、生物条件和物流列为候选自然依赖；在取得独立来源以前，这些只是候选关系，不能直接写成任何企业的实际采购量、成本冲击或股价方向。

## 最小闭环

| 步骤 | 当前做法 |
| --- | --- |
| 记录 | 从一个需求满足过程出发，记录自然依赖候选、证据和地理单元 |
| 建模 | 用低维字段表示资源供给、气候、水压力、生物条件和物流约束 |
| 验证 | 检查依赖关系是否有来源、时间语义是否安全、能否连接回产业节点 |
| 复盘 | 对自然约束、产业状态、社会分配和市场价格变化分别记录，暂不强行推断因果 |

## 第一批建议范围

在现有数据基础上，第一批只围绕“基本营养—动物蛋白—生猪过程”做最小试点：

1. 定义需求—功能—过程—自然依赖—地理单元—状态观察契约。
2. 将饲料粮、水、气候、生物条件和物流列为待核验候选，不直接认定为公司事实。
3. 选择一个免费、可归档、带历史发布时间的公开数据源完成单一依赖验证。
4. 验证通过后再扩展到其他产品或行业，避免先造一张无法连接产业用途的全球大表。
